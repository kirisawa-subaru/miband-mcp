# MiBand MCP 配置

这是随 MCP 仓库分发的组件。目标是让用户在自己的电脑开着时，通过 agent 查询手环数据。面向国内版小米运动健康和未 root 的安卓手机；已有 root 环境可使用发行包实际支持的小米健康后端。苹果手机不在本流程范围内。

用户不需要理解 ADB、密钥、数据库、端口或 MCP 配置。由 agent 完成电脑端工作、选择适用路径并验证结果，用户只承担必要的选择、手机操作和手环确认。

## 开始与选型

先读 [接入路径与实现状态](references/setup-paths.md)。检查当前发行包实际提供的后端和命令，区分安装步骤与尚未实现的功能；不要把 CLI 可读数据库报告成 MCP 已接通。

所需后端尚未提供时，先说明具体缺口，保留有用的只读检查结果；不要让用户先切换管理 App、修改手环配对或开放无线访问，再在最后发现无法完成安装。

从电脑自行识别操作系统、运行环境和 MCP 客户端。手机连接后再识别型号、安卓版本、已安装 App 和连接状态，不要求用户查版本号、包名、IP 或序列号。

只询问无法观察且影响路径的事项，沿用用户已经给出的回答：

- 手机与手环是否已经在小米运动健康中正常使用。
- 手机界面由 agent 操作，还是由用户按提示操作。未明确偏好时可问：“连接后，你希望我帮你操作手机，还是我一步步告诉你点哪里？”
- 需要切换 Gadgetbridge 时，用“改用另一个 App 管理手环”说明实际变化，再让用户选择；不要让用户选择技术后端名。用户要保留官方 App 的使用方式而当前发行包无法满足时，明确这项功能缺口，不诱导 root。

默认先用 USB 完成一条可用路径。首次授权前，引导用户插线、解锁手机、开启调试并确认这台电脑；电脑端安装和诊断由 agent 完成。用户需要登录或验证账号时，由用户在相应界面完成。

面向完全没有技术经验的用户，说明要用支持数据传输的线，可优先找手机包装盒附带的原装线。只在充电、没有连接提示时，区分线材与手机当前 USB 状态；需要用户换线就给出上述具体线索。指导查看通知栏时，说明“手指从屏幕最上边缘向下滑”，再找 USB 通知并选择“文件传输”。用户不清楚页面内容时，可以发截图，由 agent 辨认；需要时解释安卓常见截图方式为同时短按电源键和音量减键。

## 手机操作方式

自动和手动共用同一接入流程、检查点与完成标准，只改变由谁操作手机界面。

### agent 操作界面

用户接受自动操作且工具可用时，通过 ADB 截图、界面读取及输入工具操作手机；先确认当前界面，再执行输入并检查结果。ADB 连接成功不等于模拟输入可用。

模拟输入被系统拒绝、当前工具不支持，或用户不愿意时，转入下面的手动流程。用户已选择手动时，不反复要求开启模拟输入、额外安全设置或改用其他远控方式。

### 用户手动操作界面

agent 保留任务负责人角色，继续处理电脑配置、选型、日志解析和结果验证；不要把整篇教程交给用户自行执行。

1. 说明协作方式：“接下来手机上的按钮由你点，电脑上的配置我来做。我每次只告诉你当前这一步。”
2. 每次只给一个当前页面上的动作，并描述可识别的文字或图标。例如用户已在 App 首页时：“请点底部的‘我的’。打开后告诉我就好。”
3. 等用户反馈或获授权的只读观察确认页面变化，再给下一步。不要一口气列出从开调试到完成配对的整串操作。
4. 找不到入口时，询问当前页面名称或几个可见选项；需要画面且用户愿意时，再通过支持图片的渠道取得页面截图。根据实际页面调整，不要求用户辨认技术字段。
5. 系统提示出现时，用一句话解释其作用，再指出应操作的按钮。手环上的确认也按独立一步引导。
6. 用户说“完成”后，使用可用的状态、文件或连接检查核实效果。只能取得用户反馈的步骤，记录为“用户确认”，不声称已独立验证。

手动模式下不要发送 `input tap/swipe/text/keyevent`、scrcpy 输入或其他等价的代点击操作。用户仍允许的只读截图、状态查询、文件传输和安装等工作可以继续；用户若也拒绝这些手机访问，则保留电脑端工作，指导其手动导出或传送文件，并说明自动更新尚未建立。不要绕道执行用户拒绝的手机操作。

用户暂时离开时，保留已完成步骤、当前页面、操作偏好和下一动作。回来后核对当前状态继续，不从头重做；继续操作手机界面也不自动恢复为模拟触控。

### Gadgetbridge 权限与配对确认

首次权限页先说明：这是 Gadgetbridge 手机应用为连接手环、显示运行通知和可选功能申请的安卓权限，skill 与 MCP 本身不申请这些安卓权限。蓝牙扫描/连接用于手环连接；读取通知、联系人、电话等按功能选择，不一概描述为健康数据同步所必需。“发布通知”和“读取手机通知并转发到手环”是不同授权。

询问用户希望由 agent 帮忙点，还是自己点；已明确授权这一阶段时沿用选择。用户选自己点，agent 只读核对结果，不同时操作权限页。无论选择哪种方式，遇到安卓跳转到应用设置、特殊权限等页面时，都用日常语言解释页面用途与下一动作；不能让用户猜为什么跳页。用户报告完成后，以最新界面和权限状态复核，不沿用操作前的快照。

蓝牙配对确认由用户手动完成，即使其余界面允许 agent 代点。发起配对前一起说明：手机和手环可能同时弹出请求，需要两边各确认一次；手机上如有“允许访问联系人和通话记录”，健康数据连接无需勾选。agent 在确认阶段停止代点，但继续获授权的只读状态检查；连接证据已确认完成时直接推进，无需再等一句口头确认。提示仍在、超时或失败时，再引导用户处理当前一步。

## 完成数据接入

按 [接入路径](references/setup-paths.md) 执行。对国内版 Gadgetbridge 路线，agent 负责日志迁移后的文件读取、密钥解析、目标设备匹配和填写；手动用户只需按提示操作界面，必要时把导出的文件交给电脑。不要要求用户在聊天里粘贴密钥或自己搜索完整日志。

手机界面不能自动填写密钥时，将结果保存在用户电脑的私有位置，以用户选择的本地传送方式供其复制到目标 App；不要把密钥放入公开文档、普通安装日志或聊天回复。

继续配置 App 权限、数据库导出与 MCP 客户端。具体命令以发行包和本机工具为准；保留客户端已有配置。既有 root 用户也须检查设备、App 版本和配置是否匹配，不沿用开发者个人手机的默认值。

## 逐级提供无线选项

USB 路径完成并通过验证后，再提供选项，用户可以停留在任何已经可用的一档：

| 方式 | 给用户的说明 | agent 的工作 |
|---|---|---|
| USB | “插着数据线就能使用。” | 配置、拉取并验证真实数据 |
| 同一 Wi-Fi | “手机和电脑连同一个 Wi-Fi 后，可以尝试拔线使用。” | 检查无线调试条件、完成配对、发现连接并验证拔线后取数；手动模式仍逐步引导手机端操作 |
| Tailscale，可选 | “手机用流量或换了 Wi-Fi 时，也希望连接这台电脑，可以再配置跨网络访问。” | 在用户选择后部署两端网络及实际传输服务，验证换网后取数 |

Tailscale 只解决跨网络可达性，安卓端不会因此自动获得 SSH 服务、调试连接或 App 数据访问权限。需要发行包提供并实际验通手机端传输入口；没有该入口就保留可用的 USB/局域网方式，不报告跨网配置完成。不要将这一档承诺为“不间断连接”。

无线失败时先诊断网络、发现服务和调试状态，保留已配对信息；无法恢复时引导插线继续使用，不默认清除配对、解绑手环或重装 App。

## 验收与接续

- 首次完成：通过用户实际的 MCP 客户端调用工具，核对设备、数据来源与观测时间。能发现工具、能读取旧文件与取得新数据分别记录。
- 无线完成：拔线后重新取数；后续核对手机/电脑重启后的连接恢复。尚未做的恢复检查明确保留，不由一次连通推断完成。
- 跨网完成：手机离开同一 Wi-Fi 后，经实际数据通道取得记录；仅两端 Tailscale 显示在线不足以通过。
- 最近没有新观测时，报告记录时间并继续检查手环到 App 的同步，不把文件复制时间作为测量时间。

结束时用日常语言说明“现在怎么用、下次要做什么、断开时怎么恢复”。接续状态保存于用户本地的安装记录，包含已验证连接方式、操作偏好、最后检查点和下一动作；排除密钥与完整健康记录。未通过的步骤不能标记为完成。
